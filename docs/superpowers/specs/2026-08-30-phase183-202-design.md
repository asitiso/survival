# Phase 183–202 Combat Readability & Render Fidelity Design

## Goal
Polish high-skill Mythic play and foldable/mobile presentation without adding combat actions, menus, or persistent management overhead.

## Global constraints
- Keep exactly 9 combat actions: four normal spells, two ultimates, potion, shop, AUTO.
- No new blocking combat modal.
- Preserve Phase 182 snapshot compatibility.
- Prefer bounded, short-lived runtime state over new persistent schema fields.
- Preserve danger telegraph readability before decorative effects.
- Existing non-Final-Form and non-Mythic behavior remains unchanged.

## Phase 183–186 — Perfect Evade Chain
Consecutive valid PERFECT EVADE results within a bounded chain window build a 1–5 chain. The chain improves only combat-tempo rewards: Flow retention, signature charge, and a tiny short movement bonus. Being hit by an active arena hazard breaks the chain. No gold/XP farming reward is added.

## Phase 187–190 — Mythic Safe-Lane Motion
Each Mythic geometry exposes a deterministic safe-lane hint derived from current hazards and hero position. It is guidance, not auto-movement. The renderer can show a short-lived safe-space marker, while collision remains owned by BossArenaSystem.

## Phase 191–194 — Flow × Final Form Link
At Flow 5, the next Final Form signature attack receives one bounded link modifier based on mobility family. This changes attack radius/damage/chain/push behavior without adding another activation input. The link is consumed by the signature attack and cannot stack infinitely.

## Phase 195–198 — Foldable Dual Panel
Foldable layout places hero/build information left of the hinge and time/threat/status information right of the hinge. Action buttons and joystick remain outside the hinge exclusion. Standard/compact/ultrawide layouts retain current placement.

## Phase 199–202 — Raster Contract Approximation
Render Contract gains a deterministic low-resolution rasterizer over logical primitives. It produces coverage/perceptual signatures per viewport/state and a similarity score against a baseline contract. This is not a browser screenshot replacement for colors/fonts, but it detects geometry drift, missing primitives, hinge overlap, and large layout changes in CI where Chromium cannot start.

## Testing
Each subsystem gets RED→GREEN unit tests, then one Phase 183–202 integration contract, then the full repository suite, TypeScript build, diff check, HTTP smoke, render-contract audit, ZIP integrity.
