# Phase 283~302 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Finish five bounded Phase 283~302 improvements covering Tactic success feedback, Last Law safe-zone lifecycle, 12-form sound/palette identity, foldable thumb travel auditing, and one Release Manifest gate.

**Architecture:** Each feature begins as a pure deterministic module with tests, then connects to one existing runtime seam. Combat authority remains in the existing boss/geometry/finisher systems; the new modules add feedback, bounded lifecycle composition, presentation identity, audit data, and release aggregation without new player actions or persistence.

**Tech Stack:** TypeScript, Node test runner, Canvas presentation runtime, Web Audio oscillator descriptors, npm scripts.

**Spec:** `docs/superpowers/specs/2026-08-30-phase283-302-product-gate-design.md`

## Global Constraints
- Combat Action count remains exactly 9.
- No new snapshot fields or blocking UI.
- Last Law HP threshold stays unchanged.
- 12-form differences are presentation-only.
- Non-foldable input behavior stays unchanged.
- Baselines are never auto-updated.
