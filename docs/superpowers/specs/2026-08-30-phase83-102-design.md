# Phase 83-102 Endgame Replay & Mobile Polish Design

## Goal
Make late-game runs easier to reproduce, more distinct by hero/boss identity, safer to resume, and less error-prone on mobile without adding combat actions or mandatory menus.

## Global constraints
- Keep the nine combat actions unchanged: 4 normal spells, 2 ultimates, potion, shop, AUTO.
- Do not grant a finished Build Capsule loadout at run start; replay remains progression-valid.
- Reuse existing result/lobby surfaces and toast/HUD feedback instead of adding new modal flows.
- Persist only compact deterministic state; never persist enemy/projectile positions.
- Preserve every Phase 1-82 snapshot and runtime migration path.
- Performance degradation must reduce presentation density before enemy AI/spawn logic.

## Phase 83-86 — Build Capsule Replay
A Build Capsule decodes into a replay plan with the original hero, trait, threat, map and seed plus the final build as a target. Starting a replay uses only the original start conditions. Spell levels, relics, fusions, fate choices and ascensions must still be earned normally. A deterministic progress scorer reports how closely the current run matches the target build. The current replay capsule is stored in Run Snapshot so resume preserves the target.

The existing result retry button becomes a replay-aware action when a valid capsule exists. No third results button is added. A replayed run can show a compact progress line in the final build summary.

## Phase 87-90 — Mythic Last Law Identity
The generic Last Law remains the baseline envelope, but each of the six boss archetypes receives a distinct law identity and bounded modifier bias:
- Inferno: Solar Rupture — projectile pressure and vulnerability window.
- Summoner: Brood Crown — summon-heavy pressure, weaker after weakpoint clear.
- Juggernaut: Iron Verdict — dash pressure, lower projectile emphasis.
- Abyss Witch: Null Eclipse — faster special cadence and projectile control.
- Twin Maw: Twin Cataclysm — balanced dash/projectile alternating pressure.
- Time Eater: Broken Hour — cadence spike with reduced summon dependence.

Weakpoint clearing must continue to reduce total Last Law pressure. No profile may exceed existing encounter hard caps.

## Phase 91-94 — Final Form Signature Attack Patterns
When a Final Form Signature activates, it fires one bounded hero/form-specific combat pulse using the existing activation effect. Four mechanical families are supported: radial burst, chained execution, protective shockwave, and domain pulse. Twelve forms map to those families with different radius/damage/push/heal parameters. This is one pulse per signature activation, not a new per-frame subsystem.

## Phase 95-98 — Mid-run Checkpoint UX
Checkpoint milestones occur at 90, 180, 300, 480 and 720 minutes. Reaching one emits exactly once, forces a normal compact snapshot save and recovery-journal append, and shows a short checkpoint receipt. Reaching a milestone never pauses the run. Reached milestone IDs live in extension snapshot state so resume cannot duplicate rewards/receipts.

## Phase 99-102 — Mobile Touch & Frame Polish
Action hit testing chooses the closest normalized action target when inflated touch circles overlap, eliminating array-order mistakes. Joystick movement gets a small radial deadzone with continuous remapping so tiny thumb drift does not move the hero. Pointer capture semantics remain unchanged.

Frame quality policy gains a hard presentation-count budget per governor tier. These caps only affect decorative presentation objects; enemy logic remains unchanged. Existing hysteresis thresholds stay intact.

## Testing
Each subsystem gets direct tests first. Integration tests assert Game imports and wires the new modules, snapshot migration preserves replay/checkpoint state, no new ActionId exists, and legacy tests remain green. Final verification runs the full suite, TypeScript build, git diff check, HTTP smoke tests and ZIP integrity.
