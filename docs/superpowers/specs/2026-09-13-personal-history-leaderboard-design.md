# 개인 기록과 탑 순위 설계

## 목적

로그인한 플레이어가 게임 안에서 자신의 종료 기록을 확인하고, 같은 위협 단계에서 다른 플레이어의 최고 생존 기록과 비교할 수 있게 한다. 기록 저장만으로 끝내지 않고 `내 순위`, 선두와의 시간 차이, 바로 앞 순위와의 차이를 보여 주어 다음 플레이 목표를 분명하게 한다.

## 범위

- 로비에 `내 기록`과 `탑 순위` 화면을 추가한다.
- 순위는 위협 단계(T0~T5)별 최고 생존 시간으로 분리한다.
- 동률은 처치 수, 도달 레벨, 더 이른 기록 순서로 정렬한다.
- 개인 기록은 본인만 읽는다.
- 공개 순위에는 표시명, 영웅, 생존 시간, 처치 수, 도달 레벨, 위협 단계만 노출한다.
- 종료 기록을 저장할 때 DB가 해당 사용자의 단계별 최고 기록을 갱신한다.

이번 단계에서는 서버 전투 시뮬레이션 검증이나 완전한 치트 방지를 구현하지 않는다. 클라이언트가 제출하는 결과값을 완전히 신뢰할 수 없다는 한계는 유지된다.

## 데이터 모델 및 보안

기존 `run_records`에 `threat_level`과 `ended_at`을 활용해 개인 기록을 보관한다. `profiles`에는 로그인 후 설정 가능한 표시명을 둔다.

공개 읽기 전용 테이블 `leaderboard_entries`를 둔다. 키는 `(threat_level, user_id)`이며 한 사용자의 같은 T단계 최고 기록만 가진다. `user_id`는 클라이언트에 노출하지 않고 표시명과 순위 비교에 필요한 경기 요약만 반환한다.

`run_records`는 현재처럼 본인만 SELECT/INSERT 가능하다. `leaderboard_entries`는 익명·로그인 사용자에게 SELECT만 허용하며 INSERT/UPDATE/DELETE 권한은 주지 않는다. 안전한 갱신은 `run_records` INSERT 뒤의 DB 트리거가 수행한다. 트리거는 새 기록이 기존 최고보다 좋을 때만 교체한다.

## UI와 흐름

로비의 계정 영역 아래에 `내 기록`과 `탑 순위` 버튼을 둔다. 로그인하지 않은 상태에서 개인 기록은 로컬 최근 기록만 보여 주며, 탑 순위는 읽을 수 있다. Google 로그인 후에는 클라우드 개인 기록을 최근순으로 합쳐 보여 준다.

탑 순위는 현재 선택한 T단계를 기본 필터로 사용하고 T0~T5 전환을 제공한다. 상위 20명만 한 번에 표시한다. 내 행이 20위 밖이면 별도 고정 행으로 보여 준다. 비교 문구는 선두와의 생존 시간 차이와 바로 위 플레이어를 넘기기 위한 남은 시간을 표시한다.

표시명이 없는 계정은 `마도사 #XXXX` 형태의 안전한 별칭을 사용한다. 이메일, UUID, 상세 빌드, 종료 시각은 공개 순위에 표시하지 않는다.

## 클라이언트 경계

`CloudRunHistory`는 종료 기록을 저장하고 개인 기록과 리더보드 조회를 담당하는 작은 저장소로 확장한다. 게임 루프는 종료 시 저장만 요청하고 실패를 기다리지 않는다. UI는 로딩·빈 상태·오프라인 실패를 명시적으로 표시하되 플레이 시작을 막지 않는다.

## 검증

- DB 계약 테스트: RLS, 공개 읽기 전용 권한, 단계별 최고 기록 갱신 조건을 고정한다.
- 저장소 테스트: 개인 기록 필터, T단계 순위 정렬, 내 순위 비교 계산을 검증한다.
- UI 테스트: 로그인/게스트/빈 기록에서 적절한 상태를 렌더링한다.
- 실제 Supabase: SQL 적용 후 공개 SELECT와 본인 기록 INSERT를 확인하고, 같은 사용자에게 더 짧은 기록이 최고 기록을 덮어쓰지 않는지 검증한다.
